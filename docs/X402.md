# x402 v2 and paid tiers

The hosted service exposes `POST /v1/paid/tiers/agent` and `/v1/paid/tiers/pro`. When x402 is enabled, a request without payment receives HTTP 402 plus the canonical base64 `PAYMENT-REQUIRED` header. The client retries with a base64 `PAYMENT-SIGNATURE` header. The server checks the selected payment requirement, calls the facilitator's `/verify`, then `/settle`, and activates the tier only after successful settlement.

The 402 response includes a v2 `bazaar` extension describing the HTTP input and JSON output, so a compatible facilitator can index the endpoints.

## Tiers

| Tier | Exact scopes per token | Active delegations | Token TTL ceiling | Payment |
|---|---:|---:|---:|---|
| Free | 1 | 0 | 5 minutes | none |
| Agent | 8 | 5 | 15 minutes | x402 amount from environment |
| Pro | 32 | 50 | 30 minutes | x402 amount from environment |

Planned Bazaar launch pricing is $0.001 per Agent authorization and $0.005 per Pro authorization. The live atomic amounts remain operator configuration so the displayed dollar price can be matched to the selected asset correctly.

The open-source self-hosted service is not license-gated. These payments buy hosted-service capacity; they do not buy identity, imply autonomy, or replace cryptographic authorization.

## Public paid services

The hosted deployment publishes three discovery-ready Base mainnet services:

| Endpoint | Price | Result |
|---|---:|---|
| `POST /v1/paid/register` | $0.01 USDC | Registers an Ed25519 public key, activates the Agent tier, and returns a signed BOT PASSPORT. |
| `POST /v1/paid/evidence` | $0.03 USDC | Fetches a public HTTPS URL and returns a bounded point-in-time snapshot with status, provenance headers, metadata, text excerpt, and SHA-256 content hash. |
| `POST /v1/paid/freshness` | $0.01 USDC | Checks observable HTTP and publisher-declared timestamps against a requested age and returns fresh, stale, or unknown with evidence and confidence. |

The evidence service blocks local/private network destinations and does not retain request URLs or bodies. Its output is transport evidence, not a truth or authorship determination.

Agents and marketplaces can discover these endpoints through `/openapi.json`, `/.well-known/x402`, and the Bazaar extension in each runtime 402 response.

## Activation checklist

Keep `X402_ENABLED=false` until all values are deliberately configured:

```dotenv
X402_ENABLED=true
X402_FACILITATOR_URL=https://YOUR-TRUSTED-FACILITATOR
X402_NETWORK=eip155:8453
X402_ASSET=USDC_CONTRACT_ADDRESS
X402_PAY_TO=YOUR_RECEIVING_WALLET
X402_AGENT_AMOUNT=ATOMIC_UNIT_AMOUNT
X402_PRO_AMOUNT=ATOMIC_UNIT_AMOUNT
X402_REGISTER_AMOUNT=10000
X402_EVIDENCE_AMOUNT=30000
X402_FRESHNESS_AMOUNT=10000
```

Before production, confirm the facilitator supports your exact scheme/network through `/supported`, use a test network first, exercise an actual paid request end to end, verify settlement in the receiving wallet, and then check the facilitator's Bazaar discovery endpoint. Never copy the example network, asset, wallet, or price blindly.
